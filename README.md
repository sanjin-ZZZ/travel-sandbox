# 旅行沙盘 Travel Sandbox

把一份模糊的旅行想法，整理成一张能在电脑规划、在手机查看的交互旅行网页。它适合支持本地 Skill、文件读写和代码执行的 AI Agent，不绑定 ChatGPT 或某个托管平台。

## 从旅行需求到旅行沙盘

旅行沙盘不是把景点随意排进日历，而是按下面的顺序把想法变成可执行的计划：

1. **了解旅行需求**：先明确日期、人数、预算口径、出发和返程交通、体力与节奏、住宿要求，以及喜欢与不喜欢的体验。
2. **整理地点**：把景点、餐饮、咖啡、酒店、交通和休息点分成主选、替换备选与待核实项；不把还没选定的餐厅强行塞进日程。
3. **讨论行程**：按天安排大致节奏，检查城市之间的地理关系、交通时间、营业与预约条件。主线和天气替换方案分开保留。
4. **生成沙盘**：确认后把行程写入 JSON，生成包含每天怎么玩、想吃什么、住与行、旅行记账四个入口的网页。
5. **验收与交付**：在电脑和手机上检查地图、地点详情、路线、记录保存和导入导出；公开分享前必须确认这份行程可以公开。

## 页面里有什么

- **每天怎么玩**：按日期浏览当天安排。每座城市使用固定示意地图，点击地点查看说明与路线；地点坐标是插画布局，不是导航坐标。
- **想吃什么**：汇总早餐、正餐、小吃和咖啡候选，保留为什么推荐、是否已核实与替换关系。
- **住与行**：放置酒店、交通、预约、天气和出发返程提醒。候选价格不会写成真实支出。
- **旅行记账**：记录支出、退款、付款人和人数人均；支持收藏、完成标记、备注以及本地备份导入导出。

## 示例：湖山海慢游

仓库附带一份完全虚构的三日行程：第一天在湖边散步和喝咖啡，第二天去草地和山谷，第三天到海边后返程。它演示了“需求 → 地点 → 行程 → 沙盘”的完整结构，不是目的地推荐、预订建议或真实导航。

源数据在 [`assets/example-trip.json`](assets/example-trip.json)，生成后的页面在 [`examples/harbor-weekend/index.html`](examples/harbor-weekend/index.html)。下载仓库后直接用浏览器打开该 HTML 文件即可查看。

## 开始使用

1. 点击 **Code → Download ZIP**，解压完整文件夹。不要只下载 `SKILL.md`，模板、脚本、测试和参考资料都需要保留。
2. 将文件夹导入 Agent 的 Skill 目录。Codex 可放入 `~/.codex/skills/travel-sandbox/`；其他工具按自己的 Skill 安装方式操作。
3. 在新对话中输入：

> 使用 travel-sandbox 帮我做一份旅行沙盘。先了解我的时间、人数、预算和兴趣；再整理地点、讨论按天行程，确认后生成电脑和手机都能用的页面。公开分享前先向我确认。

4. 已有行程时，直接贴出已有安排，并说明哪些内容不能改、喜欢的画风、要增加或排除的地点。

## 自己生成一份沙盘

需要 Node.js 18+。先复制 `assets/example-trip.json`，用真实旅行数据替换内容；新旅行必须使用新的 `id`，输出目录必须不存在。

```sh
node scripts/generate.mjs /absolute/path/trip.json /absolute/path/new-sandbox
```

生成器会校验日期、地点、路线、住宿和人民币账本数据。它只生成 SVG 功能初稿；最终插画版仍需要按 [视觉规范](references/visual-system.md) 制作城市插画、热点和路线，再进行浏览器验收。手机交付要求见 [部署说明](references/delivery.md)。

## 重要边界

- 示例中的地点、日期、路线和预算均为虚构，不能当作真实旅行建议。
- 真实营业时间、票务、交通、酒店与价格必须在旅行年份重新核实；预订与付款由使用者自行完成。
- 数据默认只存在当前浏览器，可导入导出，但不会自动跨设备同步。
- 当前账本固定人民币，不自动换汇，也没有离线重开缓存。
- 公开页面会包含行程数据；请勿放入订单号、证件、私人住址、账单或不愿公开的备注。

## 开发与检查

```sh
npm ci
npm test
npm run rebuild
```

功能底座在 `assets/src/`，插画渲染与紧凑排版参考在 `assets/illustrated-reference/`。修改后应检查四个页面、手机布局和数据保存。
