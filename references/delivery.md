# 标准交付：在线网页 + iPhone主屏幕入口

这不是原生App，也不是离线安装。不要再引导用户选择Scriptable、本地查看器、开发者签名或PDF，除非用户主动要求改方案。

## 访问方式与发布范围

手机版是通用 HTTPS 网页，不依赖 ChatGPT、Codex 或某个 Agent 的账号。部署者登录托管平台与旅行者打开网页是两件事，不要混为一谈。

发布前说明实际访问方式：公开免登录、指定人员登录或仅本人登录，以及是否需要特定平台账号。根据当前对话确定访问范围，已有明确授权就执行，不重复询问。公开会让获得链接的人看到行程、日期和酒店候选，须获得本次旅行的公开授权；“做成手机版”本身不代表同意公开。私人站点不能只交链接而隐瞒登录门槛。用户要求公开免登录时，选择支持匿名访问的渠道，不以账号登录入口替代。

个人记账和备注由当前模板保存在访问者设备，不上传；发布前检查产物没有混入浏览器记录、备份、密钥或未经授权的私人材料。

## 按当前 Agent 的能力部署

不预设托管商，不要求使用者具备 Sites 或 GPT 账号。先发现当前 Agent 实际可调用的部署工具、连接器、CLI，以及用户已有站点与授权。用户指定的平台优先；未指定时，从已授权可用渠道中选择支持稳定 HTTPS、手机访问及所需访问权限的静态托管方式，简短告知理由后完成部署。需要新账号、费用或缺少必要授权时，只补齐该阻碍，不让用户重复选择已经可用的渠道。

- 按选定渠道的工具说明和当前官方文档执行。Sites、其他静态托管服务、用户已有服务器都是候选，不是必装清单。不因工具排序而优先选择某个平台。
- 部署完整构建目录，包含 index.html、manifest.webmanifest、icon.svg、apple-touch-icon.png 以及实际引用的城市插画等资源。保持相对资源路径，不向产品加入托管商 SDK 或账号依赖。manifest 提供主屏幕入口，不代表离线缓存。
- 同一旅行优先更新原站点，保留网址和旅行 ID。平台配置留在该旅行部署目录，不写入共享 Skill；不复制作者的账户、项目 ID、域名或凭据。若选择 Sites，遵循其技能与原生工具，并复用当前旅行的 .openai/hosting.json。
- 没有可用部署能力时，交付完整静态文件包，明确尚未上线，指出缺少的具体能力及下一步。不能捏造网址，也不能把 localhost、127.0.0.1 或依赖电脑持续运行的预览当成出门入口。

等待部署工具确认成功，返回真实最终 URL，并说明是否需要登录。修改权限后检查服务端已生效；工具允许且有匿名访问能力时，验证未登录访问，不把已登录预览当成免登录证据。遵守平台验收限制，无法匿名验证时如实说明。不同网络可达性仍需用户用手机实际打开确认；不通过隐藏代理绕过权限。

## iPhone操作卡

可直接给用户：

1. 用 Safari 打开最终网址。
2. 点“共享 → 添加到主屏幕”。不同Safari布局可能先点“更多”再共享。
3. 若出现“作为网页App打开”，开启后点“添加”。
4. 回桌面点“旅行沙盘”图标进入，先记一笔测试记录，关闭重开确认仍在，再删除测试记录。

设置随iOS版本变化；交付时核对苹果当前说明，不照搬截图中的“只有Safari才能添加”等绝对判断：
https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios

## 使用边界与迁移

- 当前版本需要联网打开，断网重新打开未保证；外部资料和导航也依赖网络。
- 不同设备、浏览器、域名和主屏幕入口之间不要假定自动同步。换入口前导出全部记录，在新入口导入同一旅行备份；提示导入是替换不是合并。
- 清除网站数据、删除入口或系统清理可能影响记录，建议定期导出。离线缓存不是账单备份，两者不能混淆。
- 更新同一旅行保留原域名/路径和旅行ID，先导出用户记录，不随意换ID导致看似丢账。其他旅行使用新ID，避免串账。
- Skill安装不包含用户的浏览器数据，也不包含先前私人版HTML备份的自动迁移；需要迁移时另做明确字段转换和用户确认。
