# 固定产品与验收

## 模板契约

默认视觉：米白纸色、深绿界面、统一插画城市地图；主景大、备选小，暖棕去程、绿色情况下的回程，沿绘制道路走。地点可点，类别用柔光与小标识突出匹配位置。底图为图片仍须有热点、路线和详情联动，不能交付一张不可交互海报。具体按 [视觉与实现规范](visual-system.md)。

电脑：左侧四入口；行程页日期条，中央沙盘与右侧当天安排/地点详情；餐饮卡片、酒店卡片、完整账本。手机：四入口固定底部，今日摘要与沙盘切换，地图完整宽度，地点索引，弹层详情；餐饮与流水分页，每页5项；记一笔与统计备份独立弹层。日期数量变化允许日期区域局部滚动，不拉长整个页面。

复用通用界面和交互；每次旅行单独制作插画、热点和路线数据。旧生成器输出属于功能初稿，需完成插画适配才能进行最终验收。

## 验收顺序

1. 运行生成器，必须通过数据校验。核对实际生成的是新旅行的日期、城市、人数、酒店晚数，不残留演示信息。
2. 电脑约1440px：逐页打开；日期切换、区域切换、类别筛选、地图点选、当天路线（含重复酒店）正确；真实链接与所选地点一致。
3. 手机约390×844和窄屏320：页面没有横向溢出；完整沙盘可见；标题不占首页；默认摘要约1—2屏；详情、输入框与底部操作可用，不被安全区挡住。较长行程通过日期切换，不把全程垂直堆叠。
4. 测试数据存储：新增/修改/删除支出和退款，预算与人均正确；收藏、完成标记、酒店标记、备注关闭重开保留。保存被阻止时必须显示错误，不假装成功。
5. 导出备份，验证导入会先确认替换；格式损坏、不同旅行ID、恶意字段要拒绝；拒绝后原数据不变。测试使用独立浏览器数据，不能清空用户真实记录。
6. 测试用例还应覆盖跨月行程、第三座城、非两人人数、没有餐饮/酒店候选、备选不进主线。运行 `npm test` 验证随包的自动化测试。
7. 发布前只上传新输出目录内完整构建产物（HTML、主屏幕资源、城市插画及实际引用的静态资源），不上传 trip.json以外的研究材料、账单备份、用户路径、登录凭据或整个工作目录。研究资料不因生成网页而自动获准公开。
8. 如能访问实体iPhone，验证Safari打开、添加主屏幕、桌面入口重开与记账。只有模拟/窄屏测试时如实说明，不能说已在真机验收。

无浏览器工具时交付本地生成物并报告“未完成视觉/交互验收”，请求用户确认实际页面；不要用字符串测试冒充浏览器验收。

## 模板升级

只有产品升级才修改 assets/src，然后在 Skill 根目录 `npm install`、`npm run rebuild`、`npm test`。重新对上述流程验收后更新模板版本。分享包保留源码、编译结果和测试，不携带 node_modules、.git、托管身份或任何旅行使用记录。

## 地图交互验收

布局与内容密度按 [需求适配](adaptive-map.md) 决定。初次进入、切日期选择day.region对应城市；同城不同日期不改变地点坐标。手动切城独立工作，每城相机状态分别保留。一次数据更新不能重置用户记录。

检查全景、1—4倍缩放、全景复位、放大后拖动、次要地点详情、跨城日期联动。电脑支持按钮或Ctrl+滚轮，手机支持按钮后单指拖动；当前没有手机双指捏合。相机只保留于本次页面会话，刷新不保证恢复。地图视窗高度受限，放大不拉长整页。地点与类别重绘不重置相机。

## 最终视觉回归

- 桌面至少检查1440×900与1280×720，逐个打开四入口：侧栏宽度、内容起点、字号一致，切页不突然放大。地图完整显示且靠左，右侧用足剩余宽度；长列表在内容区滚动，不靠缩到不可读强塞一屏。
- 逐个对照插画地名与热点：没有漏字、错名、重名、误点。不能只测DOM节点数量。
- 点地点和时间轴前后对比相机：不自动缩放；明确缩放按钮可用。切日期、类别不丢相机状态，跨城真正换图。
- 逐日检查路线沿插画道路走，不穿建筑；返程可辨、可开关、不把未选候选串入。开启减少动态效果时停用移动标识。
- 四页都去掉宣传口号、装饰英文与重复大标题，保留能帮助决定去哪、怎么走、需多久的内容；未核实项简短呈现，详细依据可展开。
- 视觉更新前后在独立测试上下文验证记录保持不变。演示账目仅经明确请求加入一次；删除后刷新不能复活。不要通过重置存储来修复视觉问题。
