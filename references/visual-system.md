# 最终视觉与实现规范

## 统一画风

默认是暖米白纸底、深绿色界面，柔和草绿与少量棕色。地图采用鸟瞰斜视插画，山体、树林、建筑有体积和层次，带轻微纸张颗粒。不是旋转3D，也不是全站手写字。界面标题可用克制的衬线字体，正文用清晰常规字体；地名在插画中统一设计，不能再叠一套粗黑白描边标签。用户另有明确参考时，以其参考为准。

每城完整绘制一张：先核对真实方位、片区、全部候选与主次，再把地形、主景、小店、道路、地名一起构图。重要节点显著大于候选（可从约两倍宽度起试，以实际构图判断），但小节点仍需看得清和点得到。名称相近的门店须核对分店。不要为了丰满虚构商家。

先生成整张样图并检查，再做交互覆盖。图像能力不足时说明缺少什么，不能偷偷退回旧模型拼贴并宣称达成该画风。生成图片后逐项核对中文、地点数量和相对关系；提示词正确不代表图片正确。修正错字或漏点后重新测热点。

## 可复用实现材料

`assets/illustrated-reference/` 包含最终方案的地图渲染器、沿路覆盖渲染器和紧凑排版CSS，已移除演示城市、路线与图片。它是适配源码，不是已接入旧生成器的模板。

在新工程中复用功能底座的 model、ledger、map-camera、phone 等模块，把参考 geography-view 与 route-art 放进同级 src；按原布局CSS → illustrated.css → compact.css 的顺序加载。对照实际DOM整理样式，不把旧的无效样式不断叠加。完整页面构建成功后替换本次输出HTML，不修改别人已发布项目。

每个无 panels 的区域补充以下 `artwork` 数据；有 panels 的总览需逐子图提供，不能引用一张总图冒充每座城：

```js
artwork: {
  src: './maps/city-complete.png',
  hotspots: { 'place-id': [cx, cy, width, height] },
  paths: { 'from-id>to-id': { d: 'M… C…', sign: [x,y] } }
}
```

参考渲染器和相机统一使用1000×670画布。图片应采用相同比例，或同时修改相机、画布和布局计算，不能拉伸图片。热点是根据完成插画实测的视觉区域，不是经纬度；保留真实地址和导航链接作为独立数据。所有已画节点都要有热点，待定位项仍留在索引。

构建前校验：每个节点恰有一个有限、正宽高且在画布内的热点；图片文件存在；每条已安排的有向路线在paths里有有效SVG路径和标识位置。缺失就修数据，不用通用直线补齐。所有字符串按上下文转义，图片只使用打包的本地资源；不要直接插入未经校验的外部SVG片段。

路径沿插画道路或留白人工绘制，暖棕去程、绿色回程、浅底描边和小箭头路牌。往返重合时稍错开。它只是行程指引，详情中的真实导航与估时另外核实。底图更新必须同步复核路径。

点地点只显示柔光、小路牌和右侧详情，手机打开详情层；不自动放大或移动。选择时间轴也保持比例，必要时切到所属城市。缩放只由用户明确操作触发。类别筛选突出匹配节点，不画虚线框。尊重减少动态效果设置。

## 全站比例与信息

四入口共用同一侧栏、紧凑顶栏、标题和正文尺寸，不把紧凑样式只挂在行程页。正文以可读为先，不为一屏无限缩小字体。去掉宣传句、装饰英文、重复标题；栏目直写“吃喝备选”“住宿与交通”“旅行记账”。

桌面地图宽度根据可用高度和图片比例计算，靠左，右侧安排吃掉剩余空间；不要给地图一大块宽容器再把图片居中留下两侧空白。完整地图在首屏；右栏长信息独立滚动，重要安排默认展开，补充说明和预订条件按需展开。参考CSS的高度常数须按当前顶栏实测调整，不是跨项目固定公式。

餐饮用紧凑卡片或列表，突出名称、类型、推荐理由、位置与收藏；酒店突出候选、日期价格状态、地点与已订标记；记账突出总额、流水与新增入口。手机保留独立布局和足够点击区域，不能照搬桌面缩小。

## 数据与交付

旅行ID、地点ID、存储键不随视觉更新变化。不得把模板作者的账目、演示种子、地图路径或域名带进新旅行。插画生成与静态托管是可替换能力，使用当前Agent实际可用工具；公开访问按用户授权，不要求GPT账号。按 standard.md 做全四页、手机、热点、路线和记录回归，再按 delivery.md 部署完整资源目录。
